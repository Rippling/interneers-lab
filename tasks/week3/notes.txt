Document Models:

1-1, 1-N, etc
Two types to store these: 1. using references... 2. using embeddings

references: the tables are separate, each entry has a field that just references another table's document
embedding: we combine both into one single big document.
ex: {
  "customer": "Aadi",
  "items": [
    { "name": "Pen", "price": 10 },
    { "name": "Book", "price": 50 }
  ]
}                                       ----> here items references this other document, which is stored as an embedding 
                                              in one single document

just look at the codes for both types.

emb is faster as we can get all the reqd data in one single query
ref is cleaner and needs less space, but slower
